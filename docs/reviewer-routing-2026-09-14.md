# 审核分配与申报界面更新

## 审核员如何确定

自动分配只在提交、重新提交及自动规律生成并提交时执行，同一条工资只有一个指定审核员。

1. 负责人已明确配置审核员：优先使用该账号。
2. 未配置：如果负责人是启用的审核员或管理员，使用负责人本人。
3. 负责人停用、不再是负责人，或明确配置的审核员已停用、被降为普通员工、不存在：不分配。明确配置失效时，不回退到负责人。
4. 非管理员审核本人工资仍需本人授权；缺少授权时不分配。

不分配的记录显示“未指定审核员，由管理员处理”。它不会对所有审核员公开。已有完整资料与工资审批授权继续生效，获授权账号可以处理该员工的待审工资，不受指定审核员限制，也不会因此改变账号角色。

“账号权限 → 查看与审核配置”可配置负责人对应审核员。选择“按负责人角色自动分配”即恢复默认规则。改变配置不会重写已有待审记录；管理员可以单独转交待审工资。转交给非管理员本人时，也会检查本人授权。重新提交会按当时的配置重新确定审核员，并保留此前提交、转交及审批快照。

本人授权后来被撤销时，原指定信息仍留在记录中，但该账号无法再自审，管理员会看到权限失效提示。单条申报、批量申报的返回结果包含已经保存的审核员分配，不必等待下一次刷新。

## 申报和显示

- 部门和计费方式可以任意顺序选择，保存时统一检查必填项。
- 交通费按本人、币种读取最后一次保存或提交时包含交通费的记录。读取完成后勾选“包含交通费”，默认填入该起终点和金额；手动改动保留，取消勾选不计费。2026-09-14 后续调整已纳入未提交草稿：保存即可更新默认值，不必提交审核；后来审批旧工资不会覆盖较新的交通费。
- 点击日期框打开站内日历，也可以用键盘输入；保留原有日期范围规则，限定申报月份的表单仍按该月校验，本人单条申报可选择其他月份。
- 放弃修改、分配/转交、作废和修改密码等弹窗限制宽度并统一留白。嵌套弹窗只响应最上层的键盘与焦点操作。
- 桌面审批卡片的部门、计费方式、工时、负责人和指定审核员排列在同一行；窄屏按两列显示。
- 顶部红色像素提醒仅播一遍，24 秒后文字清空，红框保留；无暂停按钮。减少动态效果模式下先静止显示，再清空。

## 回归和发布

本次不新增数据库迁移，不更改既有一次性部署标记，不清空日常本地数据库或线上数据。验证使用独立本地 D1/R2 数据目录；测试账号和密码不提交到仓库。

在独立本地服务上，配置测试地址、初始化密钥和测试管理员密码，先运行权限回归生成对应账号，再运行新增回归：

```sh
PAYROLL_TEST_SAVE_ACCOUNTS=1 npm run self-check:permissions
npm run self-check:reviewer-routing
```

两个命令使用同一 `PAYROLL_TEST_BASE_URL`。新增脚本拒绝非 localhost 地址和不匹配的账号文件。

新增回归覆盖默认分配、显式优先、停用和降级、自审授权及撤销、管理员自审、重新提交、手动转交、过期版本、历史快照、附件与汇总可见范围、完整资料授权、本人批量和管理员代报，以及最后一次交通费的提交顺序和币种隔离。CI 会自动运行这套检查。
