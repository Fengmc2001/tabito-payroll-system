# 2026-10-07 普通员工手机端复查

## 范围与隔离

基于本次月份、补贴、审核账号选择和 Excel 更新继续复查。使用独立本地 D1/R2 测试库，创建未来月份的边界测试工资及附件；没有连接线上数据库，没有清库，也没有改动原有本地数据库。

普通员工测试账号的角色为 `employee`，无完整资料授权、无汇总/员工管理/总审计授权。不是将管理员页面缩小后作为员工测试。

## 已确认并修复的问题

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 往期工资的长网址、连续编号撑宽页面 | 手机页面整体横向溢出 | 历史卡片允许断行，网格不再由最长内容决定宽度 |
| 批量生成等待时仍可改输入，返回后覆盖新内容 | 用户刚修改的单价等输入可能丢失 | 请求期间锁定整个批量表单，并阻止重复提交 |
| 取消补贴后生成，再次勾选带回旧杂费 | 下一批可能误带杂费 | 成功后重新初始化补贴组件；失败保留原输入，当前表单内切换勾选仍保留手动值 |
| 小屏逐日安排的时间选择和休息时长文字被挤压 | 小时、分钟难以辨认 | 手机逐日输入改为单列，时间选择浮层居中并标明开始/结束 |
| 明细历史快照的大金额与相邻栏重叠 | 窄屏金额难以阅读 | 只在详情网格中允许币种与数字换行，横向工资表保持原布局 |

以上不改变审核分配、权限、计薪、币种、作废、审计或数据库结构。新增禁用容器后的分区边框和间距也已核对保留。

## 浏览器验证

使用 Chrome 与 Playwright WebKit，开启移动视口、触摸及日本时区。覆盖宽度 320、375、390、430 像素，另检查 844 × 390 横屏与返回竖屏。

最终构建的普通员工手机专项：Chrome **359 项**、WebKit **343 项**通过。既有管理员/审核员/员工浏览器流程 **79 项**通过。月份等纯逻辑 92 项、代报界面 22 项、审批表格 101 项、资料与详情静态检查 10 项通过；ESLint、TypeScript 和生产构建均通过。

- 四个工资状态框：未提交、待审核、已驳回、已通过。每个表格内部横向滚动，外框和文档宽度保持在视口内。
- 四种状态的详情弹窗、历史快照、附件读取、滚到底部与关闭。
- 长网址、连续编号和大金额的断行；往期工资与个人资料四个标签页。
- 单条时间选择；本人批量逐日开始/结束时间、添加/删除日期、休息时长。
- 未保存离页确认：弹窗不越界，点击“继续填写”保留输入。
- 真实延迟批量请求：等待期间全部表单控件禁用；完成后旧杂费不再被带回。
- 实际保存交通费 400、餐补 800、杂费 100、工作收入 100，后端读取总额为 1,400；下次杂费为空、餐补保留。
- Chrome 执行实际模拟双指放大、表格横滑、恢复缩放，检查文档未被撑宽。WebKit 检查横滑与横竖屏切换，不将其等同于真机缩放验证。

另复跑管理员、审核员和员工的既有浏览器流程：月初默认月份、未提交补贴回填、审核账号完成标记、审批表格固定操作列、实际 Excel 下载及审核员可见范围。

复测数据和截图写入 `.local/mobile-employee-qa/{chromium,webkit}/`；既有浏览器回归结果在 `.local/october-qa/`。这些目录被 Git 忽略，不提交账号密码、工资样例、截图或导出数据。

## 复跑方式

先按 README 的顺序在一次性本地数据库运行后台、代报与权限自检，并让权限自检通过 `PAYROLL_TEST_SAVE_ACCOUNTS=1` 生成本地账号文件。不要针对正式数据运行这些测试。

```bash
npx playwright install chromium webkit
PAYROLL_TEST_BASE_URL=http://localhost:3200 npm run self-check:mobile-employee
PAYROLL_TEST_BASE_URL=http://localhost:3200 PAYROLL_TEST_ENGINE=webkit npm run self-check:mobile-employee
```

测试会核对地址为 localhost 且与账号文件一致，创建独立未来月份的测试记录。CI 已加入双浏览器检查，不会自动部署。

## 验收边界与待确认交互

- 这次不是实机 iPhone Safari / Android 浏览器测试。虚拟键盘、系统文字放大、不同系统版本及全部手势仍需真机抽查；浏览器回归通过不等于保证没有未知问题。
- 单条申报弹窗的“取消”、关闭和 Escape 仍是直接放弃本次未保存输入；切换页面有二次确认。本轮没有改变这一既有取消语义，已保存的工资不受影响。是否也在关闭弹窗时要求二次确认，可单独决定。
- 没有执行线上发布。服务器仍须沿用原 Worker、D1 和 R2 绑定，按现行保留数据部署文档更新。
