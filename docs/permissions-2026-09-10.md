# 指定审核与资料授权

## 管理员怎么设置

进入 **账号与权限 → 查看与审核配置**，先选择要设置的账号。

1. **可使用的功能**：选择工资汇总、员工管理或总审计。这里控制入口，不额外开放任何人的工资。
2. **负责人对应审核员**：若该账号是工作负责人，选择其负责的申报交给谁审核。未设置、审核员停用或降级时，新申报进入管理员待办。工作负责人本身不会因此获得查看权。
3. **可查看完整资料的员工**：勾选员工，授权该账号读取其已提交工资、历史明细、收款资料、证件和附件；包含今后提交的数据，不含未提交草稿。这是只读权限。

授予完整资料查看权时，通常同时开放“员工管理”；只需按月查看工资和收款信息时可开放“工资汇总”。保存前可取消更改。角色与查看配置分开保存；存在另一组未保存修改时会禁止交叉操作，避免覆盖。两个管理员同时修改同一账号时，旧版本的保存会被拒绝。

## 权限矩阵

| 能力 | 员工 | 审核员 | 管理员 |
|---|---|---|---|
| 本人单条、批量与自动规律申报 | 可用 | 可用 | 可用 |
| 为他人申报 | 不可 | 不可 | 可用 |
| 审批 | 不可 | 仅指定给自己的记录 | 全部待审记录 |
| 本人工资历史 | 可见 | 可见 | 可见 |
| 他人工资历史 | 需指定员工授权 | 指定审核记录；完整历史需额外授权 | 全部 |
| 申报相关附件与审批历史 | 本人或完整授权范围 | 指定记录或完整授权范围 | 全部 |
| 他人收款资料、证件 | 需完整授权 | 需完整授权 | 全部 |
| 工资汇总 | 需开放入口，按授权范围 | 默认仅本人负责部分，可切换本人及获授权员工 | 全部，可切换本人审核部分 |
| 员工管理、总审计 | 默认关闭，可单独开放 | 默认关闭，可单独开放 | 全部 |
| 授权、角色、部门和注册管理 | 不可 | 不可 | 可用 |

完整资料授权不授予审批、修改或代报权限。给审核员增加某员工的完整资料查看权后，他仍不能审批该员工分配给另一位审核员的记录。按既有运营要求，审核员可审批明确分配给自己的本人申报。

## 工资审批与汇总

- 每条已提交记录只有一个指定审核员；管理员始终可处理。负责人映射只影响后续提交。待审记录可由管理员在工资审批中“转交审核”，需核对当前记录版本。
- 审核员停用/降级后，其未处理记录不会公开给其他审核员。管理员可筛选待分配或审核员失效的记录并转交。
- 同一员工的授课费交给甲审核、提成交给乙审核时，甲的页面、接口、汇总金额和附件链接均不包含乙的提成，也不显示该员工完整月收入。
- 工资汇总可按员工、月份展开每条申报，查看明细、凭证、审核意见和历史。支付合计只包含通过的记录；JPY 与 CNY 分开统计。
- 完整资料获授权账号可在授权范围查看银行卡、PDF 与纯文本 Excel 导出。仅指定审核权限的账号不获得银行资料。
- 待审可撤回，驳回可修改重提；沿用同一记录 ID，保留原提交、驳回与重新提交历史。撤回到草稿期间，其他人暂不能查看。已通过记录不能直接修改。
- 曾提交过的申报不能作为普通草稿删除；已存入申报历史的附件不能物理删除，以保留审批依据。旧版只有审计日志而没有快照时，仅显示真实操作和备注，不伪造历史明细。

## 数据升级

新增迁移 `0007_sparkling_ares.sql`（授权、指定审核与记录历史）和 `0008_empty_mach_iv.sql`（自动规律执行负责人）。使用既有迁移命令应用，先迁移再更新服务。本次迁移不删除数据、不重算工资、不自动把旧工资开放给审核员。

- 旧记录未指定审核员，由管理员查看和处理；可逐条转交待审记录。
- 旧审核员为他人创建的自动规律停止执行。管理员在该员工的自动规律中选择“接管并启用”，原创建人不变，接管操作记入审计。员工也可接管本人的规律，不能接管别人的。
- 授权、角色和附件读取在服务端重新检查；已打开页面会定期同步账号权限。撤销不能追回对方此前已下载到设备的文件。
- 本次没有执行生产部署或清库。既有 `production_reset_20260906_v1` 一次性正式部署规则未变：完成过该重置的服务器后续更新保留正式数据；尚未完成的服务器仍需原来的备份确认。不要把本次数据库结构迁移当成清库指令。

## 验证

专项命令 `npm run self-check:permissions` 只能运行于 localhost 一次性 D1/R2，创建管理员、两名审核员、两名员工与只读查看账号，并覆盖逐条分配、不同币种隔离、直接附件访问、完整授权和撤销、功能开关、版本冲突、转交、撤回重提、历史附件、本人批量、自动规律停用与接管。测试密码只用于该隔离库；可选凭据输出位于 Git 忽略的 `.local/`，不会上传。

原有后台回归也保留：审核员查看完整资料的测试改为先由管理员显式授权；代报流程由管理员测试，不再假定审核员拥有代报权。灰度样例初始化已配置授课由阿惟审核、管理/成约由泠泠审核，并调整默认角色边界验证。
