# 完整资料与工资审批授权

管理员进入“账号权限 → 查看与审核配置”，选择被授权账号，在“可查看完整资料并审批工资的员工”中勾选员工并保存。

## 保存后的效果

- 被授权账号可查看所选员工的已申报工资、收款资料、证件及附件，并通过或驳回其全部待审工资。
- 无论工资由哪位负责人管理、指定给谁审核，或尚未指定审核员，都可以审批。指定审核员也保留原有审批权。
- 普通员工账号也适用，自动显示“工资审核 → 工资审批”，无需升为审核员或管理员。
- 现有的完整资料授权立即采用新规则，无需重新勾选；此前与今后提交的工资均适用。更新前请管理员检查已有授权名单。
- 取消勾选并保存后，新的审批请求立即重新检查权限；如果该账号仍是某条工资的指定审核员，继续保留这一条的审批权。

不包含未提交草稿、代报、修改个人资料、转交审核、权限和账号管理。这些边界未变。“工资汇总”“员工管理”“总审计”的入口仍由对应功能选项控制；工资汇总的“我负责审核的”仍指直接分配的记录，“本人及获授权员工”包含完整授权范围。

## 并发和记录

只能审批待审核记录，驳回仍必须填写原因。审批写入同时校验记录版本、账号正常状态及实时授权。两个人同时处理同一条时，只有先成功的一次生效，后续请求提示刷新；不会覆盖已经完成的审批。审计与审批历史记录实际操作账号。

本次没有数据库结构迁移，也不新增重置批次。服务器继续使用既有 `production_reset_20260913_v1` 一次性初始化规则：完成过本次初始化的服务器更新不再清库，未完成的仍须备份确认。测试使用独立本地数据库，不向日常演示库写入测试工资。

## 本次验证

- 权限接口回归 261 项：普通员工授权审批、跨负责人、未分配记录、拒绝未授权员工、草稿限制、撤销、驳回原因、版本冲突、审批历史及原有代报边界。
- SQL 授权检查 15 项：实际写入前撤销授权、停用账号、角色变化和重复决定均按实时数据库状态处理。
- 内部浏览器实测：普通员工获授权后显示审批入口，无需开放其他管理功能；实际点击通过另一位审核员负责的测试记录，确认状态变为审核通过；管理员授权名称和说明正确显示。
- 部署重置、数据迁移兼容、工资计算检查及 lint、TypeScript、构建通过。
