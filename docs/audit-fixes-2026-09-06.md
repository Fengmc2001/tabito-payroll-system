## 同时完成的本地核查修复

- 多条工时先累计分钟，再转小时；仅交通费等非计时记录不带入隐藏工时。
- 资料、工资弹窗及代报草稿增加未保存确认；保存/上传期间锁定关联操作。
- 工资弹窗等待保存完成后才关闭；失败保留输入。弹窗支持焦点约束、Tab 循环和 Escape。
- 重复触发同一消息也重新显示弹窗，嵌入提醒同时保留。
- 并行上传保留已成功附件，列明失败附件；上传期间不能增删同一列表。
- 护照超出附件数量时明确拒绝，不静默丢弃原附件。
- 代报刷新同时更新员工就绪状态和选项；工资已生成但随后列表刷新失败时，明确告知已保存并提供刷新途径。
- 批量请求成功后立即更换请求编号；定期规则失败会显示失败信息。
- 工资汇总提高表格字号并调整窄桌面布局。
- 灰度退役整个数据库阶段受同一代次条件保护，延迟到达的重复操作不会删除新正式管理员。

## 更新后的资料接口

`GET /api/users` 和 `GET /api/users/:id` 返回 `account.profileVersion`。

`PATCH /api/users/:id` 需提交 `{ profile, expectedProfileVersion }`。该版本绑定所编辑的资料快照，不随另一次登录改变。缺版本返回 400，旧快照返回 409。收到冲突时先复制未保存的输入，再刷新核对；客户端不会自动用最新版本重试覆盖。

月度提交接口现在要求 `{ month: "YYYY-MM" }`，不再接受省略月份的业务写入。仓库内网页和演示/自检脚本已同步。

## 子路径部署

根域名部署不设置 `NEXT_PUBLIC_BASE_PATH`。若访问路径为 `/payroll`，在构建及启动环境中统一设置 `NEXT_PUBLIC_BASE_PATH=/payroll`，重新构建，不能只修改浏览器 URL 或只改反向代理。既有独立 Next/Node 部署适配层需同步该配置。

本地回归示例（使用一次性数据库，先执行本地迁移）：

```bash
NEXT_PUBLIC_BASE_PATH=/payroll PAYROLL_LOCAL_STATE_PATH=.local/subpath-audit npx vite --host 127.0.0.1 --port 3503 --strictPort
# 在隔离站点初始化测试管理员后，在另一终端设置测试密码再执行
npm run self-check:subpath
```

## 本版本首次服务器发布重置

按用户确认，仅本版本第一次向某个服务器数据库发布时执行一次；之后更新保留数据，本地程序不执行。

完整提示、备份要求、初始化账号、部署凭据和失败恢复见 [服务器部署说明](server-deployment.md)。生产发布入口为 `npm run deploy:cloudflare`；只输入 `y` 才继续首次重置，`n` 或空输入中止。没有旧数据的首次正式上线无需备份，有旧数据则必须提前备份数据库及附件。

实现依据 Cloudflare 的 [D1 批量查询](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/query/)、[R2 对象列表](https://developers.cloudflare.com/api/resources/r2/subresources/buckets/subresources/objects/methods/list/)及[对象删除](https://developers.cloudflare.com/api/resources/r2/subresources/buckets/subresources/objects/methods/delete/)接口。该流程的远程权限、真实生产网络失败与最终服务器上线验收尚需部署者执行，本轮没有以生产数据试验清空。
