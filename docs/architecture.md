# 系统架构与业务模型

## 技术架构

```text
浏览器（React 19 + Hash 业务路由 + 左侧导航）
  -> Vinext / Next App Router API
      -> 会话、RBAC、输入清洗、工资重算、状态机、审计
          -> Cloudflare D1（账号、资料、工资、部门、附件元数据、审计）
          -> Cloudflare R2（私有图片/PDF 字节）
```

客户端不是权威数据源。账号角色、工资金额、状态、部门名称、币种和附件所有权都在服务端重新检查。

## 业务页面

| 编号 | 路由 | 功能 | 角色 |
|---|---|---|---|
| 01 | `#/profile/setting` | 个人、证件、联系、收款资料 | 全部 |
| 02 | `#/pay/salary` | 按自然月查看草稿、待审、驳回、通过并进行双币种工资申报 | 全部 |
| 03 | `#/pay/history` | 按月已通过工资 | 全部 |
| 04 | `#/review/salary` | 按月全状态审批、附件、最近 10 条审计 | 审核员/管理员 |
| 05 | `#/admin/users` | 账号权限、会话、密码、注册开关、动态部门 | 管理员 |
| 06 | `#/staff/employees` | 员工资料、全附件、全申报、月度工资、审计 | 审核员/管理员 |
| 07 | `#/audit/overview` | 月/年/部门/币种支出，按账号+月份追踪 | 审核员/管理员 |

## D1 表

- `payroll_users`：账号、密码派生值、角色、状态、资料 JSON、登录锁定。
- `payroll_sessions`：会话令牌摘要和过期时间。
- `payroll_salary_records`：所有者、状态、工作日期、金额、币种和完整业务快照。
- `payroll_departments`：动态部门选项、排序和软停用时间。
- `payroll_files`：R2 key、所有者、原文件名、MIME 和大小。
- `payroll_file_references`：身份证件、收款资料、工资申报与文件的规范化引用。
- `payroll_settings`：注册开关和运行时标记。
- `payroll_audit_logs`：操作人、动作、目标、安全详情与时间。

## 不变量

- 空数据库首个账号固定为 `TabitoAdimin01@tabitoedu.com`，密码由部署者自行设置。
- 工作负责人只允许“籍诚”。
- 币种只允许 `JPY`/`CNY`，任何统计不跨币种相加。
- 部门软停用不改写工资记录内的 `departmentLabel` 快照。
- 草稿才能修改/删除，待审才能通过/驳回，一条待审记录只能成功处理一次。
- 提交工资时必须指定工作月份，服务端只提交该月份的草稿，不影响其他月份。
- 已通过和已驳回记录继续归属它的 `workDate` 月份。
- 总审计选择员工账号后，月度、年度、逐月和部门汇总都只使用该员工的记录。
