# 工资申报与作废功能更新

## 员工使用

- 收款凭证栏显示“银行卡正反面/支付宝账户截图 *”，收款人是否本人补齐必填标记；仍按原规则校验收款资料。
- 件数、字数、人数、单价和交通费可清空后重新输入；空值以灰色 0 提示。输入时保留编辑文字，保存时校验数字、范围，后台也拒绝字符串等非法数值。
- 交通起点、终点、费用按本账号及币种提示上次申报的交通信息。勾选“包含交通费”才填入并计费；不勾选保存为 `- / - / 0`。切换币种会取消交通费，不做自动换算。
- 有提交历史的记录，先撤回为未提交，再点“移除”，保留为已作废；从未提交的草稿仍直接删除。
- 手机保留横向工资表，仅表格内部可左右滚动，外框不随表格撑宽。详情弹窗支持手机宽度和长文字换行。
- 本期工资申报顶部常驻红色像素字体提醒：“请【最晚】在三号之前完成上个月的工资申报并提交”。支持暂停，系统要求减少动态效果时静止显示。提醒不改变现有提交截止规则。

## 管理员使用

“账号权限 → 查看与审核配置”可以勾选所选账号本人。非管理员只有得到本人授权才可自审，即使工资原本指定给本人也不例外；取消并保存后即时撤销自审权，但仍能查看自己的工资。管理员原有完整权限不变。

“工资审核 → 工资审批”中，已通过工资有“作废”按钮。必须填写原因，并确认已核对付款情况。作废只调整系统记录和汇总，不会撤销银行或其他平台的实际转账。

管理员点击“查看已作废记录”，可按月份、员工筛选并打开原明细、提交与审批历史及附件。作废保留原金额、币种、审批结果快照、原因和操作人，不再参与正常申报、工资汇总、导出和月度/年度支出统计。

## 更新与验证

无需新增数据库迁移，也不新增清库批次。既有一次性初始化规则保持不变；不要为更新此功能重新清空数据库。

回归覆盖数字类型与范围、交通费开关及账号/币种隔离、草稿删除、历史记录作废、已通过工资作废权限与付款确认、并发版本冲突、历史与附件保留、汇总排除及本人审批授权撤销。

本次本地验证：权限接口 264 项、新增交通费与作废接口 104 项、后端回归 471 项、代报与批量申报 239 项均通过；类型检查、Lint 和生产构建通过。全部使用隔离测试库，未操作线上数据。

浏览器实测普通员工与管理员：数字清空后输入、非法字符拦截、交通费勾选与取消、收款凭证名称和必填标记、本人授权选项、作废原因与付款确认、归档详情及原审批过程。手机表格在 320、390、768 像素视口下右滑后调整宽度，页面宽度始终等于视口宽度；详情弹窗手机内边距 16 像素，桌面左右内边距 26 像素。像素字体加载、提醒暂停按钮正常，最终页面未发现浏览器错误日志。此验证不替代真实 iPhone Safari 的实机测试。

运行新增接口回归前，请先在独立本地数据库运行权限回归并保存测试账号：

```sh
PAYROLL_TEST_SAVE_ACCOUNTS=1 npm run self-check:permissions
npm run self-check:void-travel
```

两个命令需配置同一 `PAYROLL_TEST_BASE_URL`；权限回归还需测试管理员密码和初始化密钥。测试仅允许 localhost，并校验账号文件所属环境。不要对日常演示库或正式数据运行这些测试。
