# 2026-10-07 工资系统更新与验收

## 功能调整

1. **默认月份**：按日本时间计算，每月 1–3 日（含 3 日）默认上月，4 日起默认本月。本人申报、本人批量、管理员单条/批量代报、工资审批和工资汇总一致。仍可手动选月；总审计和定期规则保留原有自然月逻辑。
2. **补贴**：“包含交通费”改为“包含补贴”，可填写交通费、餐补和杂费。交通费与餐补按员工、币种记住最近保存的输入，未提交草稿也能回填；审批或一次提交多条旧草稿不会覆盖新输入。每次新建时杂费为空；当前表单取消勾选再勾选保留手动修改。批量表单的补贴金额按每条工资计算，成功生成后清空杂费。
3. **审核账号选择**：可搜索姓名，显示待审条数；当月有已通过/已驳回申报、且没有待审核记录时，显示浅绿色“当月审核完毕”。没有当月申报不标记完成。审核员的标记仅针对其当前可见申报，不表示该员工全部收入已审核。
4. **Excel**：下载真正的 `.xlsx` 文件。第一张“工资总览”注明年月，保留原汇总/收款字段；其后按可见员工生成 `姓名_2026年10月` 等明细 Sheet，包含待审、已通过、已驳回的当月工资。姓名过长、重复或包含 Excel 禁用字符时会自动处理，不会丢掉月份。日元和人民币分别统计，账号、证件号按文本保存，不丢前导零。
5. **选择时间**：空白时间选择器从 12:00 打开，分别选择小时和分钟，不用从凌晨翻起；点击“确定”才写入。已填写的时间保持原值，24:00 仅可作为原规则允许的结束时间。
6. **保留历史**：原工资金额、审批历史与附件不重新计算、不重置。餐补和杂费是工资 JSON 中的可选字段，旧数据缺省为零；本次不新增数据库迁移。

补贴适用的计费方式与原交通费一致；不勾选时三种补贴均为零。审核员分配、完整资料授权、自审授权、转交、作废、人工休息时间与币种规则未改动。

## 已有系统更新 / 重装

重新安装源码和更新运行代码可以保留数据库。关键是**继续绑定原 Worker、原 D1 和原 R2**，而不是创建新的数据库或存储桶。

部署老师操作前：

- 保存现有 `wrangler.jsonc` 的真实 Worker 名称、D1 `database_id` / `database_name`、R2 `bucket_name`、域名与路径配置；保留云端 Secret。仓库中的 D1 ID 是占位值，不能直接发布。
- 建议备份数据库与附件。代码发布脚本不代替备份，也不会自动寻找原服务器的配置。
- 更新源码后恢复上述原配置；不要运行测试初始化、灰度清理、旧版重置或删除资源命令。

```bash
# 在部署机的本项目目录中；本地改动先妥善保存
git pull --ff-only origin main
npm ci

# 沿用原资源配置，并通过秘密管理配置 Cloudflare 账号 ID 与 API Token
npm run lint
npx tsc --noEmit
npm run deploy:cloudflare
```

正常发布命令已移除旧版一次性清空步骤。它会核对现有资源绑定、检查增量迁移、构建、仅应用未执行的迁移、再次核对绑定并发布；不会清空账号、工资或 R2 附件，也不会写入演示数据。旧版清空完成标记缺失不再触发重置；若检测到旧版清理尚未完成、绑定不符或迁移包含未经批准的数据修改，则停止发布，等待人工核对。旧 `--resume` 参数不再接受。

已有数据库继续使用原账号与密码，不需要重新注册或再次初始化。只有真正的空数据库才使用固定首管理员 `TabitoAdimin01@tabitoedu.com`，需要预设至少 16 个字符的 `BOOTSTRAP_SECRET` 并自行设置密码。

完整配置步骤见 [生产服务器与域名部署](server-deployment.md)。本次开发仅使用新建本地测试库，未连接、清空或部署线上资源。
